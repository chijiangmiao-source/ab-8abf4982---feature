# 静默跳转故障规程 · 弱互模拟审计

卫星地面站故障规程复核工具：工程师在页面录入两份含静默内部跳转（`tau`）的
有限状态规程（状态、初始状态、迁移），系统判定两个初始状态是否维持相同的
**可观察承诺**（弱互模拟 / weak bisimulation）。

- 仅以 `tau` 静默跳转（含静默环、状态重命名）造成的差异 → 判定**等价**，
  最终关系对称呈现，包含两个初始状态对 `(s0, t0)` 与 `(t0, s0)`。
- 一侧的可观察动作不能由另一侧以“静默前缀后承接同动作”承接 → 判定**不等价**。
- 审查员可展开**首个淘汰状态对、挑战动作与按轮次递减的依据**；每项失败义务
  仅引用更早轮次的淘汰结果，状态对、动作、候选响应全部稳定排序，支持自底向上复算。
- 每份规程最多 **18 个状态**、**4 种可观察 ASCII 动作**与 1 种 `tau` 动作；
  状态名与迁移标识唯一。迁移端点、初始状态或动作集合无效时，**一次显示所有问题
  并清除旧结论**。

## 方向性轨迹承接检查（普通复核后的可选项）

工程师完成普通复核后，可在页面选择一个方向（A → B、B → A，或双向各一次），
检查**左侧的所有可观察动作轨迹是否均能由右侧承接**，该检查**不改变**上方弱互模拟
结论：弱互模拟等价的两个规程必然双向包含，但单向包含（轨迹偏序）不必对称——
因此双向结果可能不同。

- 引擎沿左侧一条**存在性路径**推进（左侧当前位置为单状态，同动作多落点分别分支），
  同时对**右侧做全集子集构造**：记录“右侧在已读动作前仍可能停留的状态集合”；
  静默前缀仍按既有语义在动作前展开（不吸收动作后的尾部 `tau`）。
- 一旦某动作左侧可走、而右侧停留集合（展开静默前缀后）**无任何同动作响应落点**
  （空响应），即返回反例轨迹；在所有反例中选取**长度最短、同长度按动作 ASCII 序
  最小**者。
- 为避免十八状态规程的子集搜索失控，守方集合以 **18 位位集**表示，并按左侧位置
  维护**不可互相替代的前沿**：同一左侧位置下集合严格包含时，更小的集合能导致更强
  失败结论（可响应对起始集合单调），仅当其前驱动作序列不更大时才剪枝以保 ASCII
  最小性；页面按**稳定前驱链**复算并展开反例每轮的动作、左侧位置、右侧停留集合、
  静默前缀展开集、右侧可响应落点与首个空响应。
- **切换方向、编辑任一规程、载入示例或输入校验失败时，立即清除旧的方向性结果**；
  普通审计继续可用。

接口通过可选字段 `directions` 请求：

```json
{ "procA": {...}, "procB": {...}, "directions": ["A-to-B", "B-to-A"] }
```

返回中 `traceChecks` 为按请求顺序排列的结果：包含成立时 `contained: true`、
`trace: null`；否则给出 `trace`（动作序列）、`length`、逐轮 `rounds` 与
`firstEmptyResponse`。不带 `directions` 时 `traceChecks: []`，行为与原先一致。

## 弱转移与判定

- `s ==tau=> p` 当且仅当 `s` 经任意条（含 0 条）`tau` 到达 `p`；
- `s ==a==> p`（`a` 可观察）当且仅当存在 `u`：`s` 经静默前缀到达 `u`，且 `u --a--> p`；
- 从全集关系 `R₀`（全部跨侧状态对）起逐轮淘汰：第 k 轮以上一轮存活集 `R_{k-1}`
  检查每个存活对双向义务；无存活候选响应的对在本轮淘汰，直到不动点。
  初始状态对在最终关系中即等价。失败义务引用的落点对必然在严格更早轮次淘汰。

## 本地运行（需 Node.js ≥ 20，零依赖）

```bash
npm test                 # 代码测试
npm start                # 启动服务，默认 :8080
PORT=9000 npm start      # 自定义端口
```

- 页面：`GET /`
- 健康路径：`GET /healthz`
- 审计接口：`POST /api/audit`，请求体 `{ "procA": {...}, "procB": {...}, "directions": ["A-to-B"] }`（`directions` 可选）
- 内置示例：`GET /api/samples`（等价 / 缺失动作 / 多轮级联 / 单向包含边界）

规程 JSON 形式：

```json
{
  "states": [{ "name": "S0" }, { "name": "S1" }],
  "initial": "S0",
  "transitions": [
    { "id": "t1", "from": "S0", "action": "tau", "to": "S0" },
    { "id": "t2", "from": "S0", "action": "x", "to": "S1" }
  ]
}
```

## Docker / Compose

```bash
docker compose up --build -d          # 在可配置宿主机端口暴露页面
HOST_PORT=9090 docker compose up -d   # 自定义宿主机端口
curl http://localhost:8080/healthz
```

`docker-compose.yml` 提供可执行的 `verify` 服务：等待 `web` 健康后，执行

1. 构建检查（全部源码 `node --check`）；
2. 代码测试（`node --test`）；
3. 接口 / HTTP 冒烟（健康路径、页面、审计接口：
   静默环等价规程必须判等价且含两个初始状态对；
   缺失匹配动作规程必须判不等价；无效输入必须一次返回全部问题并清除旧结论；
   方向性轨迹承接必须覆盖含静默环的轨迹包含、缺失动作的最短反例与首个空响应、
   双向结果不同的边界，以及无效输入时清除方向性结果）。

```bash
docker compose build
docker compose run --rm verify        # 完成后退出，退出码报告结果（0 成功）
echo $?
```
